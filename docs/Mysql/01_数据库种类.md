数据库主要根据数据模型、存储方式和应用场景分类，不同类型在结构、特性和适用场景上差异显著，以下是主流数据库种类及核心区别：
## 一、关系型数据库(RDBMS)

**核心特征**：基于关系模型(二维表结构)，遵循 ACID 原则(原子性、一致性、隔离性、持久性)，支持 SQL 查询，强调数据一致性。

**代表产品**：MySQL、Oracle、PostgreSQL、SQL Server、SQLite、MariaDB。

**优势**：结构严谨、事务安全、支持复杂关联查询；

**局限**：高并发读写场景下性能易瓶颈，水平扩展较复杂。

**适用场景**：金融、电商等对数据一致性要求高的业务(如订单系统、用户账户)。

**产品特点**：
1. MySQL：轻量、开源、互联网首选、主从复制成熟。
2. PostgreSQL：功能更强大、SQL 标准兼容性更好、Oracle 平替首选
3. Oracle：商业版、金融/电信核心、贵、运维复杂

## 二、非关系型数据库(NoSQL)

为解决关系型数据库在海量数据、高并发场景下的局限而生，数据模型灵活，不强制遵循 ACID(部分支持 BASE 理论：基本可用、软状态、最终一致性)。

### 2.1 键值数据库

**核心特征**：以 “键 - 值” 对存储数据，结构最简单，查询速度极快。

**代表产品**：Redis、Memcached、Amazon DynamoDB。

**优势**：超高读写性能，支持缓存、分布式存储；

**局限**：无法进行复杂查询，值类型多为字符串 / 二进制。

**适用场景**：缓存系统、会话存储、购物车数据。

### 2.2 文档数据库

**核心特征**：存储半结构化文档(如 JSON/BSON)，文档内可嵌套数据，无需固定 schema。

**代表产品**：MongoDB、CouchDB、Elasticsearch(兼具搜索引擎特性)。

**优势**：schema 灵活，支持复杂查询和索引；

**局限**：事务支持较弱(新版 MongoDB 已优化)。

**适用场景**：内容管理系统(CMS)、用户画像、日志存储。

### 2.3 列族数据库

**核心特征**：也叫分布式数据库，按列族存储数据(列族 = 多个列的集合)，适合海量数据的列级查询。

**代表产品**：HBase、Cassandra、BigTable。

**优势**：高扩展性、高吞吐量，适合分布式存储；

**局限**：事务支持弱，查询语法复杂。

**适用场景**：大数据分析、时序数据、日志系统(如 Hadoop 生态)。

### 2.4 图形数据库

**核心特征**：以节点和边存储数据，专注处理实体间的关系(如社交网络、知识图谱)。

**代表产品**：Neo4j、ArangoDB、JanusGraph。

**优势**：高效查询复杂关系，支持图算法；

**局限**：数据量大时性能下降，适用场景较窄。

**适用场景**：社交关系分析、推荐系统、路径规划。

## 三、新兴数据库类型

### 3.1 时序数据库

**核心特征**：专为时间戳数据设计，支持高写入和时序查询。

**代表产品**：InfluxDB、Prometheus、TimescaleDB。

**适用场景**：物联网(IoT)数据、监控指标、金融行情。

优势是压缩率高、写入极快；局限是基本不支持关联查询。
### 3.2 向量数据库

**核心特征**：存储和检索向量数据，支持相似度匹配。

**代表产品**：Milvus、Pinecone、FAISS(Facebook)。

**适用场景**：AI 语义检索、图像识别、推荐系统。

优势是毫秒级检索亿级向量；局限是需要 GPU 资源加速，且语义准确性依赖模型。
### 3.3 多模数据库

**核心特征**：融合多种数据模型(如关系 + 文档 + 图形)，适配复杂场景。

**代表产品**：MongoDB 5.0+、CockroachDB、OceanBase。

**适用场景**：需要同时处理多种数据类型的业务(如电商 + 社交融合系统)。

优势是一套系统搞定多种数据；局限是各模块性能不如专用数据库极致。


## 四、核心区别总结表
### 4.1 数据库差异
| 维度 | 关系型数据库 | NoSQL 数据库 | 时序数据库 | 向量数据库 |
|------|-------------|--------------|-----------|-----------|
| 数据模型 | 二维表 | 键值 / 文档 / 列族 / 图形 | 时间序列 | 向量 |
| 一致性 | 强一致性(ACID) | 最终一致性(BASE) | 弱一致性 | 弱一致性 |
| 查询语言 | SQL | 非 SQL / 类 SQL | SQL 扩展 | 向量检索 API |
| 扩展性 | 垂直扩展为主 | 水平扩展为主 | 水平扩展 | 水平扩展 |
| 适用场景 | 事务型业务 | 海量数据 / 高并发 | 时序数据监控 | AI 语义检索 |

### 4.2 数据库选择
| 你的需求             | 推荐类型                  | 理由                |
| ---------------- | --------------------- | ----------------- |
| 需要事务、多表关联、SQL标准  | 关系型(MySQL/PostgreSQL) | 成熟稳定，保证ACID       |
| 超高并发读写，纯缓存或简单KV  | 键值型(Redis)            | 内存操作，微秒级响应        |
| 数据结构多变，嵌套深，快速迭代  | 文档型(MongoDB)          | Schema-less，开发效率高 |
| 海量写入，按时间查询，聚合统计  | 时序型(InfluxDB)         | 专门优化时间窗口和聚合       |
| 社交关系、路径搜索、推荐     | 图型(Neo4j)             | 关系遍历比SQL快成千上万倍    |
| 超大规模宽表，列数不定，写多读少 | 列族型(Cassandra/HBase)  | 水平扩展能力极强          |
| 做AI应用，需要向量相似度检索  | 向量型(Milvus)           | 提供高效ANN搜索         |
