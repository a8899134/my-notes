# MySQL 笔记

MySQL（读音 /maɪ ˌɛs kjuː ˈɛl/）是一款开源的关系型数据库管理系统（RDBMS），由瑞典公司 MySQL AB 开发，目前隶属于 Oracle 公司。其名称来源于创始人 Michael Widenius 的女儿 "My"。MySQL 凭借其高性能、高可靠性和易用性，已成为全球最流行的开源数据库之一，广泛应用于互联网、电商、金融等各行业。Facebook、Twitter、YouTube 等大型互联网公司均深度依赖 MySQL 作为核心数据存储。

MySQL 官方文档网址：https://dev.mysql.com/doc/

MySQL 官方下载网址：https://dev.mysql.com/downloads/

## 为什么选择 MySQL

- 性能卓越：针对读密集型和 OLTP 场景深度优化，配合 InnoDB 存储引擎，读写性能表现优异
- 稳定可靠：支持事务、崩溃恢复、在线热备，提供完整的数据安全保障机制
- 成熟生态：作为最主流的开源数据库，拥有丰富的周边工具和第三方中间件
- 开源免费：采用 GPL 许可证，社区版功能已满足绝大多数场景需求
- 持续演进：Oracle 主导下稳步迭代，8.0 版本引入窗口函数、CTE、JSON 支持等现代数据库特性

## 核心功能
1. 关系型数据管理：支持 ACID 事务、外键约束、视图、存储过程、触发器、游标等完整关系型数据库特性
2. SQL 标准支持：兼容 SQL:2003 标准，支持复杂查询、子查询、连接查询、窗口函数、公共表表达式
3. 多存储引擎：支持 InnoDB、MyISAM、Memory、Merge、Archive 等多种存储引擎，灵活适配不同场景
4. 复制架构：支持主从复制、半同步复制、组复制（MGR）、异步复制，构建高可用读写分离集群
5. 高可用方案：支持 MHA、MGR、Orchestrator、Keepalived 等多种高可用架构，保障业务连续性
6. 分区支持：支持 RANGE、LIST、HASH、KEY 等分区方式，海量数据管理更高效
7. 全文检索：支持自然语言全文检索和布尔全文检索（InnoDB 和 MyISAM 引擎）
8. JSON 支持：自 5.7 版本起提供原生 JSON 数据类型和 JSON 函数，融合 NoSQL 能力
9. 连接管理：支持长连接、连接池、线程池，有效管理数据库连接资源

## 架构原理

MySQL 采用 C/S 架构，其核心组件分为以下几个层次：
```text
客户端连接 → 连接层 → SQL 层 → 存储引擎层 → 文件系统层
```
1. 连接层（Connection Layer）
- 连接管理：负责客户端连接的建立、认证（用户名/密码/主机验证）和权限校验
- 线程池：为每个连接分配独立线程（旧版）或使用线程池复用（企业版/插件）
- 安全传输：支持 SSL/TLS 加密连接

2. SQL 层（Server Layer）
- 查询缓存（8.0 已移除）：缓存 SELECT 查询结果，提高重复查询效率
- 解析器（Parser）：对 SQL 语句进行词法分析和语法分析，生成解析树
- 预处理器（Preprocessor）：检查解析树的语义正确性（表、列是否存在，权限校验）
- 优化器（Optimizer）：基于成本模型选择最优执行计划，包括索引选择、连接顺序优化、子查询优化等
- 执行器（Executor）：调用存储引擎接口执行查询，返回结果集

3. 存储引擎层（Storage Engine Layer）
MySQL 的核心特色在于 插件式存储引擎 架构。存储引擎负责数据的存储与读取，不同引擎拥有不同的特性和适用场景。

| 存储引擎 | 特点 | 适用场景 |
|----------|------|----------|
| InnoDB | 支持事务、行锁、外键、MVCC，默认引擎 | 绝大多数 OLTP 场景（推荐） |
| MyISAM | 不支持事务，表级锁，查询速度快 | 只读/报表类历史遗留场景（8.0 已废弃） |
| Memory | 数据存储在内存，重启丢失，速度极快 | 临时表、缓存表 |
| Archive | 高压缩比，只支持 INSERT/SELECT | 日志归档、审计数据 |

4. 文件系统层
- 数据文件：.ibd（InnoDB 表空间）、.frm（表结构，8.0 合入数据字典）
- 日志文件：redo log（重做日志）、undo log（回滚日志）、binlog（二进制日志）
- 系统表空间：存储数据字典、双写缓冲区、变更缓冲区等

## 典型应用场景

- Web 应用后端数据库：作为 LAMP/LEMP 栈中的标准数据存储组件
- 电商交易系统：利用 InnoDB 的事务能力确保订单、库存数据一致性
- 内容管理系统（CMS）：存储文章、用户、配置等结构化数据
- 数据仓库/报表系统：配合列式存储引擎或中间件进行数据分析（大数据量场景建议配合 ClickHouse 等）
- SaaS 多租户应用：支持库内多租户隔离或分库分表方案
- 读写分离架构：一主多从架构分担查询压力，提升系统吞吐量

> 📌 **总结**：MySQL 凭借其插件式存储引擎架构、完善的 InnoDB 事务引擎、成熟的复制生态以及活跃的开源社区，已成为互联网行业事实标准的开源关系型数据库。无论是作为中小型应用的首选数据存储方案，还是作为大型分布式系统的基础数据层组件，MySQL 都能在性能、可靠性和成本之间取得良好的平衡。对后端开发者和运维工程师而言，深入理解 MySQL 的索引机制、事务原理及复制架构，是构建高可用数据系统的关键能力。
