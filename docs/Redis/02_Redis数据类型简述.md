## 一、数据类型概述
### 1.1 基本概念
Redis 中所有的 Key(键)都是字符串类型，而 Value(值) 则支持多种不同的数据类型。选择合适的数据类型，可以让业务开发更高效、代码更简洁。

可以把 Redis 理解为一个“存储柜”，Key 是每个柜子的编号(永远是一个字符串)，Value 是柜子里存放的东西。不同类型决定了你能往柜子里存什么、怎么存取。
### 1.2 五种核心数据类型
| 数据类型             | 核心特性              | 适用场景            |
| ---------------- | ----------------- | --------------- |
| String(字符串)      | 二进制安全，可存文本/数字/二进制 | 缓存、计数器、分布式锁     |
| Hash(哈希)         | 键值对集合，适合存对象       | 用户信息、商品详情、配置参数  |
| List(列表)         | 有序可重复，支持头尾操作      | 消息队列、最新列表、操作日志  |
| Set(集合)          | 无序不可重复，支持集合运算     | 去重、共同好友、随机抽奖    |
| Sorted Set(有序集合) | 有序不可重复，按分数排序      | 排行榜、延迟队列、带权重的任务 |
### 1.3 扩展数据类型简述
除五种核心类型外，Redis 还提供了几种扩展数据类型，用于特定场景：

|扩展类型|核心特性|适用场景|
|---|---|---|
|BitMap(位图)|按位存储，节省空间|用户签到、在线状态、布隆过滤器|
|HyperLogLog|基数统计，误差约 0.81%|UV 统计、独立访客数|
|GEO(地理空间)|存储经纬度，支持距离计算|附近的人、门店搜索、导航|
|Stream(流)|持久化消息队列|消息总线、事件溯源、日志采集|

## 二、字符串(String)
### 2.1 基本概念
这是 Redis 最基础、最简单的类型。一个 Key 对应一个 Value，Value 不仅可以是常见的 “Hello World” 文本，也可以是数字(如 100)，甚至是图片或序列化对象的二进制流。

生活比喻：就像一个带编号的独立储物柜，你放进去什么，拿出来的就是什么。
### 2.2 常用命令
#### 2.2.1 SET — 设置键值对
**格式**：`SET key value [EX seconds] [PX milliseconds] [NX|XX]`

**说明**：设置指定 Key 的 Value。如果 Key 已存在，默认覆盖旧值。

**参数说明**(可选)：
- EX seconds：设置过期时间(单位：秒)
- PX milliseconds：设置过期时间(单位：毫秒)
- NX：仅当 Key 不存在时才设置(用于分布式锁)
- XX：仅当 Key 存在时才设置

**示例**：
```text
SET name "张三"
```
返回：`OK`
```text
SET session:123 "abc123" EX 1800
```
返回：`OK`(同时设置 30 分钟后过期)
```text
SET lock "1" NX
```
返回：OK(Key 不存在时设置成功；若已存在则返回 nil)
#### 2.2.2 GET — 获取值
**格式**：`GET key`

**说明**：获取指定 Key 的 Value。如果 Key 不存在，返回 `(nil)`。

**示例**：
```tex
GET name
```
返回：`"张三"`
```text
GET not_exist_key
```
返回：`(nil)`
#### 2.2.3 DEL — 删除键
**格式**：`DEL key [key ...]`

**说明**：删除一个或多个 Key。返回成功删除的数量。

**示例**：
```text
DEL name
```
返回：(integer) 1
```text
DEL name age email
```
返回：`(integer) 3`
#### 2.2.4 SETEX — 设置值并指定过期时间
**格式**：`SETEX key seconds value`

**说明**：设置键值对，同时指定过期时间(单位：秒)。与 `SET key value EX seconds` 效果相同。

**示例**：
```text
SETEX verify_code 60 123456
```
返回：`OK`(验证码 60 秒后自动失效)
#### 2.2.5 SETNX — 仅当 Key 不存在时设置
**格式**：`SETNX key value`

**说明**：Set if Not eXists。仅当 Key 不存在时才设置。返回 1 表示设置成功，返回 0 表示 Key 已存在。

**示例**：
```text
SETNX lock "1"
```
返回：`(integer) 1`(第一次设置成功)
```text
SETNX lock "1"
```
返回：`(integer) 0`(再次设置失败，lock 已存在)
#### 2.2.6 INCR — 数字自增
**格式**：`INCR key`

**说明**：将 Key 中存储的数字值加 1。如果 Key 不存在，则先初始化为 0，再执行 INCR。如果 Key 的值不是数字类型，会返回错误。

**示例**：
```text
INCR page_view
```
返回：`(integer) 1`
```text
INCR page_view
```
返回：`(integer) 2`
#### 2.2.7 DECR — 数字自减
**格式**：`DECR key`

**说明**：将 Key 中存储的数字值减 1。如果 Key 不存在，则先初始化为 0，再执行 DECR。

**示例**：
```text
DECR stock
```
返回：`(integer) -1`
#### 2.2.8 INCRBY — 增加指定数值
**格式**：`INCRBY key increment`

**说明**：将 Key 中存储的数字值增加指定的整数。

**示例**：
```text
INCRBY score 10
```
返回：`(integer) 10`
```text
INCRBY score 5
```
返回：`(integer) 15`
#### 2.2.9 MSET — 批量设置

**格式**：`MSET key value [key value ...]`

**说明**：一次性设置多个键值对。比多次执行 SET 更高效，减少了网络往返次数。

**示例**：
```text
MSET name "张三" age "25" city "厦门"
```
返回：`OK`
#### 2.2.10 MGET — 批量获取
**格式**：`MGET key [key ...]`

**说明**：一次性获取多个 Key 的值。不存在的 Key 返回 `(nil)`。

**示例**：
```text
MGET name age city
```
返回：
1. `"张三"`
2. `"25"`
3. `"厦门"`
#### 2.2.11 APPEND — 追加内容
**格式**：`APPEND key value`

**说明**：在原有 Value 后面追加内容。返回追加后字符串的总长度。

**示例**：
```text
SET name "张"
```
返回：`OK`
```text
APPEND name "三"
```
返回：`(integer) 3`
```text
GET name
```
返回：`"张三"`
#### 2.2.12 STRLEN — 获取字符串长度
**格式**：`STRLEN key`

**说明**：获取字符串 Value 的长度(字节数)。中文字符在 UTF-8 编码下占 3 个字节。

**示例**：
```text
SET name "张三"
```
返回：OK
```text
STRLEN name
```
返回：(integer) 6("张三" 在 UTF-8 下占 6 个字节)
### 2.3 典型应用场景
1. 缓存热点数据
将数据库查询结果缓存到 Redis，设置合理的过期时间，减轻数据库压力。例如：用户信息、商品详情、配置数据。
2. 计数器
利用 INCR 和 DECR 的原子特性，实现高并发下的计数。例如：文章阅读数、商品库存扣减、接口调用次数限制。
3. 分布式锁
利用 SETNX 或 SET NX 实现分布式锁，配合 EX 设置超时时间，防止死锁。例如：防止商品超卖、定时任务防重复执行。
4. 短信/邮件验证码
利用 SETEX 设置验证码并指定过期时间，到期自动失效。
5. 存储 Token / Session
存储用户登录凭证，设置过期时间实现自动登出。

## 三、哈希(Hash)
### 3.1 基本概念
哈希是一个键值对的无序集合，特别适合用来存储对象。打个比方，存储一个“用户”，如果使用 String，需要把名字、年龄、邮箱拼成一个字符串，改一个字段就得全取出来再塞回去。而使用 Hash，你可以把对象看作一个档案袋，里面每个字段(Field)都是独立的标签页，可以单独读写。

生活比喻：一个贴满了标签页的档案袋。你可以只看“姓名”这一页，也可以只修改“年龄”这一页，无需把整个档案袋拆开。
### 3.2 常用命令
#### 3.2.1 HSET — 设置字段值
**格式**：`HSET key field value [field value ...]`

**说明**：为哈希表中一个或多个字段设置值。如果字段是新增的，返回 1；如果字段已存在被覆盖，返回 0。

**示例**：
```text
HSET user:1001 name "张三"
```
返回：`(integer) 1`
```text
HSET user:1001 age "25" city "厦门"
```
返回：`(integer) 2`
#### 3.2.2 HGET — 获取字段值
**格式**：`HGET key field`

**说明**：获取哈希表中指定字段的值。如果字段不存在，返回 `(nil)`。

**示例**：
```text
HGET user:1001 name
```
返回：`"张三"`
```text
HGET user:1001 email
```
返回：`(nil)`
#### 3.2.3 HDEL — 删除字段
**格式**：`HDEL key field [field ...]`

**说明**：删除哈希表中的一个或多个字段。返回成功删除的字段数量。

**示例**：
```text
HDEL user:1001 age
```
返回：`(integer) 1`
```text
HDEL user:1001 age email
```
返回：`(integer) 1`(age 已不存在，只删除了 email)
#### 3.2.4 HGETALL — 获取所有字段和值
**格式**：`HGETALL key`

**说明**：获取哈希表中所有字段和值。返回结果按照“字段 1，值 1，字段 2，值 2……”的顺序排列。

**生产环境注意**：如果哈希表中字段较多，此命令可能耗时较长，请谨慎使用。

**示例**：
```text
HGETALL user:1001
```
返回：
1. `"name"`
2. `"张三"`
3. `"city"`
4. `"厦门"`
#### 3.2.5 HKEYS — 获取所有字段名
**格式**：`HKEYS key`

**说明**：获取哈希表中所有字段名。**生产环境注意**：字段较多时可能耗时，请谨慎使用。

**示例**：
```text
HKEYS user:1001
```
返回：
1. `"name"`
2. `"city"`
#### 3.2.6 HVALS — 获取所有值
**格式**：`HVALS key`

**说明**：获取哈希表中所有值。**生产环境注意**：字段较多时可能耗时，请谨慎使用。

**示例**：
```text
HVALS user:1001
```
返回：
1. `"张三"` 
2. `"厦门"`
#### 3.2.7 HEXISTS — 判断字段是否存在
**格式**：`HEXISTS key field`

**说明**：检查哈希表中是否存在指定字段。存在返回 1，不存在返回 0。

**示例**：
```text
HEXISTS user:1001 name
```
返回：`(integer) 1`
```text
HEXISTS user:1001 email
```
返回：`(integer) 0`
#### 3.2.8 HLEN — 获取字段数量
**格式**：`HLEN key`

**说明**：获取哈希表中字段的总数量。

**示例**：
```text
HLEN user:1001
```
返回：`(integer) 2`
#### 3.2.9 HINCRBY — 字段数字自增
**格式**：`HINCRBY key field increment`

**说明**：将哈希表中某个字段的数字值增加指定数量。如果字段不存在，则先初始化为 0，再执行增加。

**示例**：
```text
HINCRBY user:1001 score 10
```
返回：`(integer) 10`
```text
HINCRBY user:1001 score 5
```
返回：`(integer) 15`
### 3.3 典型应用场景
1. 存储对象信息
以对象 ID 为 Key，对象属性为 Field，属性值为 Value。例如：用户信息、商品详情、订单数据。
2. 存储配置参数
将系统配置项以 Hash 存储，方便单独读取或修改某个配置。
3. 购物车
以用户 ID 为 Key，商品 ID 为 Field，商品数量为 Value，实现购物车功能。
### 3.4 何时不适合使用 Hash
Hash 适用于字段数量相对固定的对象。如果字段数量极大(上千个)或单个 Value 很大，建议评估是否适合用 Hash，可考虑拆分为多个 String Key。

## 四、列表(List)
### 4.1 基本概念
Redis 列表是一个有序的字符串列表，底层实现是双向链表。这意味着你可以从列表的左边(头部)或右边(尾部)推入(Push)或弹出(Pop)元素。因为链表不涉及大量数据的移动，所以头尾操作的性能极高，O(1) 时间复杂度。

生活比喻：一个两头都可以进出的排队通道。你可以从左边进去，也可以从右边进去；从左边出来，或者从右边出来。
### 4.2 常用命令
#### 4.2.1 LPUSH — 从左侧插入
**格式**：`LPUSH key value [value ...]`

**说明**：从列表左侧(头部)插入一个或多个元素。先插入的元素在更左侧。返回插入后列表的长度。

**示例**：
```text
LPUSH tasks "task1"
```
返回：`(integer) 1`
```text
LPUSH tasks "task2" "task3"
```
返回：`(integer) 3`
此时列表顺序：`task3` → `task2` → `task1`
#### 4.2.2 RPUSH — 从右侧插入
**格式**：`RPUSH key value [value ...]`

**说明**：从列表右侧(尾部)插入一个或多个元素。返回插入后列表的长度。

**示例**：
```text
RPUSH queue "A"
```
返回：`(integer) 1`
```text
RPUSH queue "B" "C"
```
返回：`(integer) 3`
此时列表顺序：`A` → `B` → `C`
#### 4.2.3 LPOP — 从左侧弹出
**格式**：`LPOP key [count]`

**说明**：移除并返回列表左侧(头部)的第一个元素。如果指定 count，则移除并返回多个元素。列表为空时返回 `(nil)`。

**示例**：
```text
LPOP tasks
```
返回：`"task3"` ( 移除并返回最左侧)素)
```text
LPOP tasks 2
```
返回：`"task2"` `"task1"`
#### 4.2.4 RPOP — 从右侧弹出
**格式**：`RPOP key [count]`

**说明**：移除并返回列表右侧(尾部)的最后一个元素。如果指定 count，则移除并返回多个元素。列表为空时返回 `(nil)`。

**示例**：
```text
RPOP queue
```
返回：`"C"`(移除并返回最右侧元素)
#### 4.2.5 LRANGE — 获取指定范围的元素
**格式**：`LRANGE key start stop`

**说明**：获取列表中指定范围的元素。索引从 0 开始，-1 表示最后一个元素，-2 表示倒数第二个，以此类推。

**示例**：
```text
LRANGE tasks 0 -1
```
返回：列表中的所有元素
```text
LRANGE tasks 0 2
```
返回：前 3 个元素
```text
LRANGE tasks -2 -1
```
返回：最后 2 个元素
#### 4.2.6 LINDEX — 获取指定索引的元素
**格式**：`LINDEX key index`

**说明**：获取列表中指定索引位置的元素。索引从 0 开始，负数表示从尾部开始计算。

**示例**：
```text
LINDEX tasks 0
```
返回：第一个元素
```text
LINDEX tasks -1
```
返回：最后一个元素
#### 4.2.7 LLEN — 获取列表长度
**格式**：`LLEN key`

**说明**：获取列表的长度(元素个数)。

**示例**：
```text
LLEN tasks
```
返回：`(integer) 3`
#### 4.2.8 BLPOP — 阻塞式左侧弹出
**格式**：`BLPOP key [key ...] timeout`

**说明**：从列表左侧弹出元素。如果列表为空，则阻塞等待，直到有元素可弹出或超时。timeout 单位为秒，设为 0 表示永久等待。

**示例**：

```text
BLPOP tasks 30
```
返回：如果 30 秒内有元素，返回弹出的元素；否则超时返回 `(nil)`
#### 4.2.9 BRPOP — 阻塞式右侧弹出
**格式**：`BRPOP key [key ...] timeout`

**说明**：从列表右侧弹出元素。如果列表为空，则阻塞等待。与 BLPOP 类似，只是方向相反。

**示例**：
```text
BRPOP queue 30
```
返回：从右侧弹出元素，等待时间最长 30 秒
### 4.3 典型应用场景
1. 消息队列
生产者使用 RPUSH 向队列尾部放入消息，消费者使用 LPOP 或 BLPOP 从队列头部取出消息。BLPOP 的阻塞特性可以避免消费者空轮询，节省 CPU 资源。
2. 最新消息列表
如微博时间线、新闻列表，使用 LPUSH 将新内容插入头部，LRANGE 分页读取。
3. 操作日志
记录用户最近的操作历史，可配合 LTRIM 限制列表长度，只保留最近的 N 条记录。
4. 栈或队列
LPUSH + LPOP 实现栈(后进先出)，LPUSH + RPOP 实现队列(先进先出)。
### 4.4 注意事项
列表的元素数量如果过大(百万级)，执行 LLEN 或 LRANGE 0 -1 会遍历整个列表，可能导致 Redis 阻塞。生产环境中应避免对这些大列表执行全量操作。

## 五、集合(Set)
### 5.1 基本概念
Redis 集合是一个无序的字符串集合，并且其中的元素是唯一(不允许重复)的。它最强大的地方在于支持数学中的集合运算：交集(共同好友)、并集(全部好友)、差集(我独有)。

生活比喻：一个不许放重复东西的抽奖箱。你往里丢东西，重复的会被弹开；而且你无法决定哪个先被拿出来(无序)。
### 5.2 常用命令
#### 5.2.1 SADD — 添加元素
**格式**：`SADD key member [member ...]`

**说明**：向集合中添加一个或多个元素。返回成功添加的元素数量(已存在的元素不重复计数)。

**示例**：
```text
SADD tags "redis" "database" "cache"
```
返回：`(integer) 3`
```text
SADD tags "redis" "nosql"
```

返回：`(integer) 1` (redis 已存在，只新增了 nosql)
#### 5.2.2 SREM — 删除元素
**格式**：`SREM key member [member ...]`

**说明**：从集合中删除一个或多个元素。返回成功删除的元素数量。

**示例**：
```text
SREM tags "database"
```
返回：`(integer) 1`
#### 5.2.3 SMEMBERS — 获取所有元素
**格式**：`SMEMBERS key`

**说明**：获取集合中的所有元素。**生产环境注意**：如果集合元素较多(万级以上)，此命令可能耗时较长，建议使用 SSCAN 替代。

**示例**：
```text
SMEMBERS tags
```
返回：
1. `"redis"`
2. `"cache"`
3. `"nosql"`
#### 5.2.4 SISMEMBER — 判断元素是否存在
**格式**：`SISMEMBER key member`

**说明**：判断指定元素是否在集合中。存在返回 1，不存在返回 0。

**示例**：
```text
SISMEMBER tags "redis"
```
返回：`(integer) 1`
```text
SISMEMBER tags "mysql"
```
返回：`(integer) 0`
#### 5.2.5 SCARD — 获取集合大小
**格式**：`SCARD key`

**说明**：获取集合中元素的总数量。

**示例**：
```text
SCARD tags
```
返回：`(integer) 3`
#### 5.2.6 SRANDMEMBER — 随机获取元素
**格式**：`SRANDMEMBER key [count]`

**说明**：随机获取集合中的一个或多个元素，但不移除这些元素。与 SPOP 的区别在于不会修改集合。

**示例**：
```text
SRANDMEMBER lottery 1
```
返回：随机一个元素(集合不变)
#### 5.2.7 SPOP — 随机弹出元素
**格式**：`SPOP key [count]`

**说明**：随机移除并返回集合中的一个或多个元素。适合抽奖等随机场景。

**示例**：
```text
SPOP lottery 1
```
返回：随机一个元素
```text
SPOP lottery 3
```
返回：随机的 3 个元素
### 5.3 典型应用场景
1. 标签系统
为文章或商品打标签，利用集合的去重特性。可以快速计算拥有某个标签的所有文章。
2. 共同好友/推荐
利用 SINTER 计算共同关注、共同好友。利用 SDIFF 计算可能认识的人。
3. 去重统计
统计独立访客 IP、唯一用户数等。
4. 抽奖系统
利用 SPOP 随机抽取中奖者，确保同一人不会被重复抽中。
5. 用户权限/角色
存储用户的权限集合，快速判断用户是否有某个权限(SISMEMBER)

## 六、有序集合(Sorted Set )
### 6.1 基本概念
有序集合和集合一样，成员也是唯一的。但不同的是，每个成员都会关联一个分数(Score)，Redis 会自动按照这个分数从小到大给成员排序。这使得它天生就适合做排行榜。

生活比喻：一份按考试成绩(分数)排名的班级花名册。你可以快速知道谁是第一名(最高分)，也可以截取第 10 名到第 20 名的区间。
### 6.2 常用命令
#### 6.2.1 ZADD — 添加元素
**格式**：`ZADD key score member [score member ...]`

**说明**：向有序集合中添加一个或多个元素及其分数。如果元素已存在，则更新其分数。返回成功添加的元素数量(不包含更新分数的已有元素)。

**可选参数**：
- `NX`：仅当元素不存在时才添加
- `XX`：仅当元素存在时才更新分数
- `GT` / `LT`：仅当新分数大于/小于当前分数时才更新

**示例**：
```text
ZADD rank 100 "张三"
```
返回：`(integer) 1`
```text
ZADD rank 95 "李四" 88 "王五"
```
返回：`(integer) 2`
```text
ZADD rank 120 "张三"
```
返回：`(integer) 0` (张三已存在，分数更新为 120)
#### 6.2.2 ZREM — 删除元素
**格式**：`ZREM key member [member ...]`

**说明**：从有序集合中删除一个或多个元素。返回成功删除的元素数量。

**示例**：
```text
ZREM rank "王五"
```
返回：`(integer) 1`
#### 6.2.3 ZRANGE — 按分数从小到大获取元素
**格式**：`ZRANGE key start stop [WITHSCORES]`

**说明**：按分数从小到大排序，获取指定排名范围内的元素。索引从 0 开始，-1 表示最后一个。加上 `WITHSCORES` 选项可同时返回分数。

**示例**：
```text
ZRANGE rank 0 -1
```
返回：按分数从小到大排列的所有成员
```text
ZRANGE rank 0 2 WITHSCORES
```
返回：前 3 个成员及其分数
#### 6.2.4 ZREVRANGE — 按分数从大到小获取元素
**格式**：`ZREVRANGE key start stop [WITHSCORES]`

**说明**：按分数从大到小排序，获取指定排名范围内的元素。排行榜中最常用的命令。

**示例**：
```text
ZREVRANGE rank 0 10 WITHSCORES
```
返回：排行榜前 10 名及其分数
#### 6.2.5 ZRANK — 获取排名(从小到大)
**格式**：`ZRANK key member`

**说明**：获取元素在有序集合中的排名(从小到大，排名从 0 开始)。如果元素不存在，返回 `(nil)`。

**示例**：
```text
ZRANK rank "张三"
```
返回：`(integer) 0`(张三分数最高，排名第 0)
#### 6.2.6 ZREVRANK — 获取排名(从大到小)
**格式**：`ZREVRANK key member`

**说明**：获取元素在有序集合中的排名(从大到小，排名从 0 开始)。这就是排行榜中的“第几名”。

**示例**：
```text
ZREVRANK rank "张三"
```
返回：`(integer) 0` (张三分数最高，排名第 0 位，即第 1 名)
```text
ZREVRANK rank "李四"
```
返回：`(integer) 1` (李四排名第 2)
#### 6.2.7 ZINCRBY — 增加分数
**格式**：`ZINCRBY key increment member`

**说明**：将指定元素的分数增加指定的数值(可以是正数或负数)。返回更新后的分数。

**示例**：
```text
ZINCRBY rank 5 "张三"
```
返回：`"125"` ( 张三从 120 变为 125)
```text
ZINCRBY rank -10 "李四"
```
返回：`"85"` ( 李四从 95 变为 85)
#### 6.2.8 ZCARD — 获取元素数量
**格式**：`ZCARD key`

**说明**：获取有序集合中元素的总数量。

**示例**：
```text
ZCARD rank
```
返回：`(integer) 3`
#### 6.2.9 ZCOUNT — 按分数范围统计
**格式**：`ZCOUNT key min max`

**说明**：统计分数在指定范围内的元素个数。min 和 max 默认包含边界，可使用 `(` 表示不包含边界。

**示例**：
```text
ZCOUNT rank 90 100
```
返回：分数在 90 到 100 之间的元素数量
```text
ZCOUNT rank 90 (100
```
返回：分数 >= 90 且 < 100 的元素数量
### 6.3 典型应用场景
1. 排行榜
游戏积分榜、热搜榜单、销售额排名。ZREVRANGE 取前 N 名，ZREVRANK 查询用户排名。
2. 延迟队列
将任务 ID 作为元素，任务执行时间戳作为分数。消费者定期用 ZRANGEBYSCORE 获取已到执行时间的任务。
3. 带权重的消息队列
分数表示消息的优先级，分数越低优先级越高，消费者优先处理分数小的消息。
4. 区间查询
如按价格区间搜索商品、按年龄范围筛选用户。
5. 限流控制
用时间戳作为分数，统计固定时间窗口内的请求数，实现接口限流。

## 七、四大高级数据类型
除了上述几种基础类型，Redis 还提供了几种高级数据类型，它们在特定场景下能发挥惊人的效率。
### 7.1 Bitmap(位图)
严格来说，Bitmap 不是一种独立的数据结构，而是对 String 类型的按位操作扩展。它将字符串的每一位(Bit)当作一个独立的状态位(0 或 1)。
- 常用命令：SETBIT、GETBIT、BITCOUNT。
- 生活比喻：一张巨大的打卡表，每天只记录“来”或“没来”(1 或 0)。
- 应用场景：用户每日签到(一年只需 365 位)、用户在线状态统计。内存占用极小。
### 7.2 HyperLogLog
这是一种专门用来做基数统计(即统计不重复元素个数)的算法，优点是占用内存极小(无论统计多少数据，每个 Key 固定只占约 12 KB)。
- 常用命令：PFADD、PFCOUNT、PFMERGE。
- 生活比喻：一个非常省空间的去重计数器，它不存具体元素，只大概估算有多少种。
- 应用场景：统计网站的 UV(独立访客数)、搜索关键词的唯一数量。注意：它返回的是近似值(误差约 0.81%)，不适用于需要精确计数的场景(如金额)。
### 7.3 GEO(地理空间)
Redis 3.2 版本引入的功能，用于存储经纬度坐标并计算距离和范围。
- 常用命令：GEOADD、GEODIST、GEORADIUS(查找半径内的点)。
- 生活比喻：一张电子地图，你存进去的是地址(经纬度)，可以查两点距离或附近的人。
- 应用场景：打车软件叫车(查找附近的司机)、社交软件的“附近的人”、外卖配送范围判断。
### 7.4 Stream(流)
这是 Redis 5.0 引入的、专门用于消息队列和事件溯源的数据类型。它像一个只能追加的日志，支持消费者组(Consumer Group)和消息确认机制(ACK)，解决了以往用 List 做消息队列时消息易丢失、不支持分组消费的痛点。
- 常用命令：XADD(生产消息)、XREAD(读取消息)、XREADGROUP(分组读取)。
- 生活比喻：一个永不关闭的广播电台，听众可以分组收听，且能确认自己收到了哪条消息。
- 应用场景：构建轻量级、高可靠性的日志收集系统或内部微服务消息总线。

## 八、使用要求规范
### 8.1 Key 命名规范
建议使用“业务名:对象名:ID”的格式，便于管理和维护。

**规范示例**：
- `user:profile:1001` — 用户 1001 的个人信息
- `order:detail:20240801` — 订单详情
- `cache:product:list:hot` — 热门商品列表缓存
- `ratelimit:api:login` — 登录接口限流

**避免不规范命名**：
- 不要使用空格、中文字符或特殊符号
- 避免命名过于简短(如 `u:1`)导致可读性差
### 8.2 注意事项
1. 避免使用 KEYS 命令
KEYS 会扫描全库，在大数据量时阻塞 Redis。所有需要遍历的场景，都应使用 SCAN 系列命令替代。
2. 避免大 Key
单个 Key 的 Value 过大(String 超过 10 KB，集合元素超过 1 万)，会影响 Redis 的性能和内存使用。建议拆分大 Key 或使用压缩。
3. 设置合理的过期时间
生产环境中，缓存类数据应设置 TTL，避免无用的 Key 长期占用内存，最终撑爆内存。
4. 使用批量命令减少网络开销
在需要多次操作时，优先使用 MGET、MSET、Pipeline 等批量方式，减少网络往返次数。
5. 生产环境禁止使用 FLUSHALL / FLUSHDB
这些命令会清空数据，生产环境应禁用或重命名。
6. 监控内存使用
定期通过 INFO memory 监控内存使用率，设置合理的 maxmemory 和淘汰策略。
7. 使用 Pipeline 批量操作
当需要执行大量连续命令(如批量写入 1000 条数据)时，使用 Pipeline 可将多条命令打包一次发送，显著减少网络往返次数(RTT)，提升吞吐量。
